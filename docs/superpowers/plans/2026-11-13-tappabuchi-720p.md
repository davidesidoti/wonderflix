# Tappabuchi 720p Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** quando non c'è niente in 1080p, "Serve te" propone il miglior 720p (film, episodio o pack di stagione) come tappabuchi che l'admin sceglie se scaricare.

**Architecture:** un terzo tipo di tappabuchi (`Quality`) nella regola (`DownloadRule`), un pack 720p per le stagioni che non si dividono (`SeasonPackRule`), il grab dell'admin che lo manda diretto a qBittorrent quando il push lo rifiuta per qualità, e l'app che spiega la proposta.

**Tech Stack:** .NET 9 (plugin Jellyfin, xUnit), Flutter 3.47.5 (Riverpod 3).

**Spec:** `docs/superpowers/specs/2026-11-13-tappabuchi-720p-design.md`

## Global Constraints

- Solo 720p: `release.Quality?.Quality?.Resolution == 720`. Mai 480p/SD.
- Il giro automatico non scarica mai un tappabuchi Quality: solo "Scarica il migliore intanto" (`GrabBest`) lo prende.
- Precedenza in `ChooseStopgap`: Score → Size → Quality.
- Un 720p è tappabuchi solo se è scartato **solo** per la qualità: tutti gli altri controlli (`ReleaseChecks`, peso minimo GB/h, rifiuti Arr che non sono di qualità) devono passare.
- Upgrade da Quality: punteggio del nuovo ≥ punteggio attuale **e** `WouldImport`.
- Stagioni: si decide sulla sola ricerca della stagione (niente ricerche per episodio).
- Codice in inglese, commenti/doc/commit in italiano. Commit senza `Co-Authored-By` e senza le parole closes/fixes/resolves.
- Plugin 1.31.0 (anche `InfoControllerTests`), app 0.42.0 con la riga nuova della checklist in `docs/RELEASING.md` nello stesso commit del bump.
- Test plugin: `dotnet test Jellyfin.Plugin.WonderFlixWatchParty.Tests --configuration Release` da `plugin/`. App da `app/`: `flutter gen-l10n`, `flutter analyze`, `flutter test`.
- Mai `taskkill /IM`/`pkill`. Build release dell'app: `flutter build windows --release --dart-define-from-file=config/wonderflix.json`.
- `dart format` solo sulle righe cambiate.

## Review Focus

1. Un 720p scartato per qualità **e** per seeders/peso/termini non diventa tappabuchi → test in Task 1.
2. Una stagione con un solo singolo 1080p (anche sotto punteggio o leggero) nei risultati si divide, niente proposta 720p → test in Task 2.
3. Il giro con un tappabuchi Quality disponibile non scarica niente da solo (resta `NeedsYou`) → test in Task 3.
4. `GrabBest` su una stagione senza `StopgapKind == Quality` non scarica (le altre stagioni restano senza `GrabBest`) → test in Task 3 e 4.
5. Una voce Quality che riceve un 1080p con punteggio più basso del 720p non lo scarica → test in Task 5.

### Task 1: il tappabuchi Quality nella regola

**Files:**
- Modify: `plugin/Jellyfin.Plugin.WonderFlixWatchParty/Downloads/ReleaseChecks.cs` (`Check`)

- Modify: `plugin/Jellyfin.Plugin.WonderFlixWatchParty/Downloads/DownloadBook.cs` (`DownloadStopgaps`, `DownloadSummary`)
- Test: `plugin/Jellyfin.Plugin.WonderFlixWatchParty.Tests/DownloadRuleTests.cs`, `ReleaseChecksTests.cs`

**Interfaces:**
- Produces:
  - `ReleaseChecks.Check(ArrRelease r, ChecksContext c, int runtimeMinutes, int? seasonMinutes = null, bool skipQuality = false)`: con `skipQuality` salta solo il controllo "qualità non ammessa".
  - `RuleRejected(ArrRelease Release, string Reason, string? Detail, bool QualityOnly = false)`: `QualityOnly` true se l'unico motivo è la qualità non ammessa e la release passa anche il peso minimo. Il `Reason` resta quello di oggi (`NotWanted` / `Arr`).
  - `DownloadStopgaps.Quality = "Quality"`.
  - `DownloadRule.ChooseStopgap(RuleResult rule)` restituisce `(release, DownloadStopgaps.Quality)` dopo Score e Size: il primo dei `QualityOnly` con risoluzione 720, nello stesso ordine di `Choose` (punteggio desc, risoluzione desc, peso asc, seeders desc, priorità indexer, guid). Siccome `ChooseStopgap` non ha la priorità indexer, ordinare senza (punteggio, peso asc, seeders desc, guid).
  - `DownloadSummary.StopgapKind` (string?) = `ChooseStopgap(rule).Kind`.
  - `DownloadRule.StopgapKindOf(int score, long sizeBytes, int runtimeMinutes, bool isMovie, double minGbPerHour, int minScore, int resolution = 0)`: se `resolution is > 0 and <= 720` restituisce `Quality` prima di tutto il resto.
  - `DownloadRule.IsQualityRejection(string text)`: true se il testo contiene "is not wanted in profile" (OrdinalIgnoreCase). Pubblico: lo usa anche Task 4.

- [ ] **Step 1: test che falliscono** in `DownloadRuleTests`:

  - `ArrQualityRejectionCountsAsQualityOnly`: release Arr con `Rejections = ["HDTV-720p is not wanted in profile"]` → stopgap Quality.
  - `A720pRejectedAlsoForSeedersIsNoStopgap`: 720p non ammesso con seeders sotto il minimo → `(null, null)`.
  - `A720pTooLightIsNoStopgap`: 720p non ammesso sotto `MinGbPerHour` → `(null, null)`.
  - `A480pIsNeverAStopgap`: 480p non ammesso → `(null, null)`.
  - `ScoreAndSizeStopgapsBeatQuality`: 1080p sotto il punteggio minimo + 720p QualityOnly → kind `Score`; 1080p troppo leggero + 720p → kind `Size`.
  - `AnArrRejectionBesidesQualityIsNotQualityOnly`: rifiuti `["HDTV-720p is not wanted in profile", "Release is blocklisted"]` → nessun tappabuchi.
  - `StopgapKindOfKeepsQualityFor720p`: `StopgapKindOf(..., resolution: 720) == "Quality"`; con 1080 e file buono → null.
  In `ReleaseChecksTests`: `SkipQualityIgnoresOnlyTheQualityCheck` (720p non ammesso → null con `skipQuality: true`; con seeders bassi → `("NotWanted","Seeders")`).
